# 个人数据授权与判定服务约定（Profile 草案 v0.1）

> 状态：**草案，供讨论**。本文件不是标准，是一份**轮廓（profile）**：在已有的智能体工具通道（如 MCP）之上，约定"个人一侧"如何**声明、授权、判定、留痕**。欢迎被引用、被批评、被拆改。

## 0. 定位与非目标

**定位**：管的是「**这个人允不允许某个程序读他的数据、并按他的方法给出判断**」。
**不在范围**：应用侧"允不允许被智能体操作"（如 SAEP 一类）——两者不同层，可叠加。

**非目标**（刻意不做）：
- 不另造传输层：能用 MCP / HTTP 就不再发明一套。
- 不要求数据上云：判定在本机完成，对外只交换**声明、请求与结论**。
- 不规定业务内容：信号、阈值、权重、规则属于**作者的方法资产**，本约定只管**怎么声明与怎么调用**。

## 1. 三个角色

| 角色 | 是谁 | 职责 |
|---|---|---|
| 所有者 | 个人（如"张律师"） | 决定哪些切片对外可用、授权给哪个程序、边界与有效期 |
| 调用方 | 外部智能体 / 程序 | 先读声明，再按契约提交，拿结论与留痕编号 |
| 宿主 | 智能体运行环境 | 提供程序身份（进程身份或票据），不得替所有者做授权决定 |

## 2. 能力声明（服务目录）

所有者应能对外提供一份**机器可读的服务目录**，至少包含：

```json
{ "space": "个人可信数据空间",
  "services": { "count": 3, "catalog": [
    { "kind": "judgment", "name": "并购估值", "owner": "<主体ID或名称>",
      "call": "POST /v1/scenario-slices/<id>/judge",
      "price": { "unit_price": 1200, "currency": "CNY" },
      "limit": { "max_amount": 1000000000, "no_resale_required": true,
                 "allowed_purposes": ["投资判断","并购估值"] },
      "validity": { "valid_days": 30, "expires_at": "…", "expired": false },
      "ready": true,
      "inputs": [ { "name":"行业", "type":"enum", "allowed":["房地产","新能源"],
                    "required": true, "example":"新能源" } ] } ] } }
```

要求：
- **R2.1** 每条服务必须能回答"叫什么、谁提供、怎么调、多少钱、什么限制、是否就绪"。
- **R2.2** `kind` 区分**判定服务**与**场景动作**；同类服务字段一致。
- **R2.3** **一一条目对应一个可调用事物**；不得用"系统内部工具名"充当服务（如"读取目录""授权检查"属**宿主能力**，不是服务）。
- **R2.4** `inputs[]` **必须**给出字段的**类型与取值范围**（`enum` 须列全 `allowed`），并给 `example`。只给字段名不算声明。

## 3. 契约声明（调用前把条件说清）

每条服务应提供契约，至少含：**字段与必填性**、**缺项语义**、**允许用途**、**金额上限**、**是否要求不转售**、**会返回什么**、**不会返回什么**、**有效期**、**授权前提**。

- **R3.1** 缺项时**不得猜测**：返回"信息不足，无法判断"并**列出缺哪几项**。
- **R3.2** **必填项的判定权在所有者**，调用方不得自行认定某项"可选"。
- **R3.3** 契约必须写明 `you_will_not_receive`（例如不返回方法原文、阈值、权重、规则）。
- **R3.4** 契约与授权是**两件事**：读得到契约 ≠ 调得动（见第 5 节）。

## 4. 判定与预演

- **R4.1** 判定**必须可溯源**：结论应说明来自**打分线 / 组合规则 / 例外**中的哪一个（如 `decided_by`）。
- **R4.2** **预演（dry-run）**：应提供不产生后果的试算接口（返回缺项与约束检查，不落结论）。
- **R4.3** 结论应带**严重度**与**依据**；依据引用的是**可公开的来源**（法条、标准），不是作者的算式。

## 5. 授权模型

- **R5.1** **默认拒绝**：未声明的空白**不等于默许**（边界为空 ⇒ 拒绝）。
- **R5.2** 授权**逐动作、逐调用方**（grantor × grantee × action × resource），可**随时撤销**。
- **R5.3** 授权规则应有状态：`draft`（待所有者确认）→ `active` → `suspended/revoked`；**只有 `active` 参与判定**。
- **R5.4** 身份优先用**宿主可核验的程序身份**（如内核判定的进程身份）；无此条件时可用**票据**，但票据必须可撤销且有期限。

## 6. 分级披露

- **R6.1** 每项服务应声明其**披露档位**：`basic` / `standard` / `professional` / `audit`（由少到多）。
- **R6.2** 调用方可请求**更低**的档位，**不得**请求高于声明档位。
- **R6.3** 任何档位都**不得**包含方法资产（权重、阈值、规则原文、例外条件）。

## 7. 留痕

- **R7.1** **每一次对外调用都要留档**，包括**被拒绝的调用**（这是最该留痕的一类）。
- **R7.2** 记录至少含：调用方、用途、金额、时间、结论或拒绝原因、记录编号、所用档位。
- **R7.3** 调用方可**凭编号**向所有者提出复核；留痕不得成为泄露方法资产的渠道。

## 8. 一致性清单（可勾选）

- [ ] 提供机器可读的服务目录，且每条可调用事物一条
- [ ] 每条服务的 `inputs[]` 含类型、取值范围、必填性、示例
- [ ] `enum` 字段列全可选值，且**不在其他地方做数字比较**
- [ ] 契约含"会返回/不会返回"与缺项语义
- [ ] 缺项时返回"信息不足"并列出缺项，不猜
- [ ] 结论可溯源（打分线 / 组合规则 / 例外）
- [ ] 提供预演接口（不产生后果）
- [ ] 边界为空 ⇒ 默认拒绝
- [ ] 授权逐动作、可撤销、有 draft/active 状态
- [ ] 拒绝也留痕，记录含编号
- [ ] 分级披露可被调用方请求降低，不可升高
- [ ] 任何档位都不含权重/阈值/规则原文

## 10. 与既有协议的关系

| | 应用侧协议（如 SAEP） | 本约定 |
|---|---|---|
| 回答的问题 | 这个应用允不允许被智能体操作 | 这个人允不允许某程序读我的数据并给判断 |
| 落地方式 | 声明 + 界面级操作 | 声明 + **真正的服务调用** |
| 层次 | 应用 ↔ 智能体 | 个人 ↔ 调用方 |
| 关系 | **可叠加**，不冲突 | —— |
