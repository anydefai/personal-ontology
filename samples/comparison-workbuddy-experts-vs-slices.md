# WorkBuddy「专家」与「个人本体切片」对比

> 结论一句话：**它卖"AI 像一个专家"，我们卖"专家本人的方法可以被安全调用并留痕"。** 前者胜在规模与易用，后者胜在权威、确定性与可追责；二者不是替代关系，而是**可叠加的两层**。

依据：WorkBuddy 官方文档 [专家 | WorkBuddy](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Expert-Center)（专家 = 「人设 + 方法论 + 工具链」的**角色切换**机制；专家团 = 多专家并行协作；创建靠写提示词；官方对其免责声明为"不构成专业意见"）。我们的口径依据本仓库实现（`samples/profile-personal-service-v0.1.md`、`samples/open-items.md`）。

## 一、功能对比

| 维度 | WorkBuddy 专家 | 我们的切片 |
|---|---|---|
| 本质 | LLM **角色化**：以专家口吻与视角完成任务 | **专家方法由引擎确定性执行**：阈值 / 信号 / 组合规则 / 例外 / 维度权重 / 依据 |
| 权威来源 | 提示词与平台 | **署名的自然人**（主体，如"张律师"） |
| 确定性 | 同一输入可能得到不同结论 | 同一输入**必得同一结论**（参数化引擎，非即兴生成） |
| 可溯源 | 会话记录 | 每次调用留档，**含被拒绝的调用**；结论可说明来自打分线 / 组合规则 / 例外 |
| 方法资产保护 | 不适用（方法即提示词） | **分级披露**（basic / standard / professional / audit）；权重、阈值、规则原文**永不外泄** |
| 调用限制 | 无 | **允许用途白名单 + 金额上限 + 不得转售**；未声明即拒绝 |
| 数据位置 | 对话与文件上传平台 | **本机加密容器**，判定不出机，对外只交换声明、请求与结论 |
| 预演 | 无 | **dry-run**：不产生后果的试算（返回缺项与约束检查） |
| 计费 | 平台积分（专家团为单专家 3–5 倍） | 切片自带**每次调用单价**（当前为演示值） |
| 责任 | 官方免责："仅供参考，不构成专业意见；涉医疗 / 法律 / 投资 / 合规请咨询专业人士" | 结论来自**具名专家设定的方法**，可凭报告编号向所有者复核 |
| 组合形态 | 专家团自动拆解、并行执行 | 每个场景 / 切片是**可被外部调用的服务**（不含"AI 团队"概念） |

## 二、商业模式

| | WorkBuddy | 我们 |
|---|---|---|
| 收入形态 | 订阅 + 积分（专家团高消耗） | 设想为**按次计费**：专家本人定价，平台可收撮合 / 通道费 |
| 专家分成 | 专家作为**留存功能**，本人不分钱 | **专家本人可分钱**（定价写在切片里） |
| 规模效应 | 强：专家中心按行业浏览、一键召唤、市场分发 | 弱：**没有分发**，目前只是一台本机服务 |
| 成本结构 | 每次调用消耗模型积分 | **每次判定几乎零模型成本**（确定性引擎），成本在建设与维护 |
| 成熟度 | 平台化、企业版、生态连接器齐备 | 单机可用，无渠道、无信用体系、无结算 |

## 三、易用性（我们明显落后）

| 环节 | WorkBuddy | 我们 |
|---|---|---|
| 上手 | 专家中心浏览 → 一键召唤 → 自然语言下任务 | 建切片 → 填 11 项字段 → 配边界（用途 / 上限 / 不转售）→ 批准调用程序 |
| 失败模式 | 少见 | 边界为空即默认拒绝；**重建切片会丢边界配置**；调用程序需先批准 |
| 现状评价 | 零配置、面向大众 | **专家工具**，需要作者与所有者都懂一点 |

**改进方向**：模板化 + 一键实例化（把"配边界 / 批准程序"变成引导步骤），并把"重建不继承配置"这条坑修掉。

## 四、受众群体

| | WorkBuddy 专家 | 我们 |
|---|---|---|
| 人群 | 普通知识工作者、中小企业员工 | **需要署名与可追责**的专业场景 |
| 诉求 | 马上有人把活干了，不在乎结论谁背书 | 结论要能签名、能复核、能担责 |
| 典型场景 | 写文档、做表格、运营、资料整理 | 律师意见、评估报告、尽调结论、合规审查、保险 / 医疗的规则化判定 |
| 规模与客单 | 面广、客单低 | 面窄、客单高、责任敏感 |

## 五、判断

1. **不是替代关系**：一个是"通用助手 + 角色化"，一个是"专家方法的可调用化 + 授权与留痕"。
2. **各自的命门**：WorkBuddy 的命门是**权威性**（它自己声明不构成专业意见）；我们的命门是**分发与易用**（没有渠道，也没有"一键"）。
3. **最好的组合**：WorkBuddy 作为**入口**，我们的切片作为**被调用的服务提供方**。它已支持 MCP / 连接器，我们已有服务目录与契约，技术上只差一次对接。
4. **一句话**：它规模化"像专家"，我们保证"是专家的方法、且调用可追责"。二者叠加才是完整图景。

## 六、我们该补的（对照结论）

- 分发：让切片能被外部发现（服务目录对外 + 一份可引用的 profile）
- 易用：模板化创建、边界引导、重建继承配置
- 信用：把"署名的专家 + 留痕 + 可复核"做成可验证的凭证，而不是靠自我介绍
