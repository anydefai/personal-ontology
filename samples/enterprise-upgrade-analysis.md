# 从「个人数据空间」到「企业数据空间」：可行性、市场对比与升级清单

> 一句话结论：**我们真正能卖的不是"更聪明的知识库"，而是"专家方法被确定性执行、且每次调用可授权可追溯"的那层治理能力。** 企业市场上，这层能力恰好是最贵、最缺的一块。

## 一、我们现在有什么（决定升级的起点）

已跑通的能力（本仓库实现）：

- **方法即资产**：领域专家把判断方法写成可执行规则（信号 / 组合规则 / 例外 / 阈值 / 维度权重 / 依据），引擎按规则算出结论。
- **确定性**：同一输入必得同一结论；结论可说明来自打分线 / 组合规则 / 例外。
- **契约与目录**：对外提供机器可读的服务目录与调用契约（字段类型与取值范围、必填、缺项语义、允许用途、金额上限、不转售、会返回什么 / 不会返回什么）。
- **分级披露**：basic / standard / professional / audit，调用方只能请求更低档位；任何档位都不含方法原文、阈值与权重。
- **授权与默认拒绝**：逐动作授权、可撤销、有 draft / active 状态；边界为空即拒绝；身份优先用可核验的进程身份。
- **留痕**：每次对外调用都留档，**含被拒绝的调用**；可凭编号复核。
- **私有优先**：数据本机加密，判定不出机，对外只交换声明 / 请求 / 结论。

## 二、升级到企业版：三个变，三个不变

**必须变的**

| 项 | 个人版 | 企业版 |
|---|---|---|
| 主体模型 | 自然人 | 组织 + 岗位 + 部门 + 外部合作方（多租户） |
| 授权模型 | 一人授权 | RBAC（角色）→ ABAC（属性：部门 / 数据分级 / 项目）＋ 组织审批流 |
| 方法归属 | 个人署名 | 团队署名 + 版本与审批（谁改的方法、谁批的、何时生效） |
| 合规 | 自我约束 | 等保 / 审计导出 / 数据分级分类 / 留存期限 / 离职交接 |
| 部署 | 单机 | 私有化 / 专有云 / 信创适配；与企业身份源（AD / LDAP / SSO）对接 |
| 集成 | 本机 MCP | ERP / OA / CRM / 数据仓库 / 工单 / 文档系统 |
| 商业 | 按次 | 订阅 + 席位 + 按次；对公结算、发票、SLA |

**绝对不能变的（这是我们的命根）**

1. **私有优先**：数据与判定留在企业边界内，不上云。
2. **方法资产不外泄**：权重、阈值、规则原文永不进调用方视野。
3. **默认拒绝**：未声明即拒绝，没有"默认放行"。
4. **留痕含拒绝**：审计不留白。
5. **结论可溯源**：任何结论都能回答"怎么来的"。

## 三、市场对比：四类玩家

> 以下均为公开信息；我们按"谁写规则 / 权威来自哪里 / 授权与留痕 / 部署 / 商业模式"五条来比。

### 第 1 类：企业本体 / 决策操作系统型

代表：**Palantir Foundry + AIP**；国内 **百型智能 企业本体 OntoZ**（WAIC 发布）。参见 [Palantir and Dell Build an AI OS](https://www.nasdaq.com/articles/palantir-and-dell-build-ai-os-paranoid)、[百型智能发布企业本体 OntoZ](https://www.cnstock.com/commonDetail/747257)。

- 谁写规则：**平台实施团队 + 客户数据团队**（本体建模是项目制）。
- 权威来源：**数据与本体本身**。
- 授权与留痕：有权限体系与审计，但**结论溯源**通常面向工程，而非"某位专家署名的方法"。
- 部署：私有化 / 专有云，重实施。
- 商业：大单 + 实施费，客单价极高。

**与我们的关系**：他们是"把企业全部数据与对象建成一张图"的重活；我们是"把某个专业判断方法变成可调用服务"的轻活。**可以共存**：我们的切片可以是他们本体之上的一类"决策服务"。

### 第 2 类：语义层 / 知识图谱 + LLM 型

代表：**Timbr**、**Databricks Genie Ontology**、**Neo4j / Stardog** 等。参见 [Timbr vs Databricks Genie Ontology](https://timbr.ai/timbr-vs-databricks-genie-ontology/)、[主流 LLM 图谱系统全景](https://github.com/cdavid817/AI-Infra-Tutorial/blob/5902fb7404417704ca3f5e535e350fbbf5b92791/%E9%99%84%E5%BD%95/%E9%99%84%E5%BD%95K-%E4%B8%BB%E6%B5%81LLM%E5%9B%BE%E8%B0%B1%E7%B3%BB%E7%BB%9F%E5%85%A8%E6%99%AF.md)。

- 谁写规则：数据团队写语义模型。
- 权威来源：**模型 + 查询**。
- 授权与留痕：偏数据库权限与查询日志。
- 商业：按节点 / 按算力 / 按查询。

**与我们的关系**：他们回答"数据是什么、怎么查"；我们回答"按谁的方法、能得出什么结论、谁批的、留没留痕"。**我们的差异化在"方法与责任"，不在"数据规模"。**

### 第 3 类：可信数据空间 / 合规底座型

代表：**安恒信息「可信数据空间 + 数据工厂」**等，以及国家层面推进的可信数据空间方向。参见 [安恒信息 CTO 专访](https://app.xinhuanet.com/news/article.html?articleId=202608299260cb2e5c7740a2bc2142316ebaf646)。

- 谁写规则：合规与安全团队。
- 权威来源：**政策与合规要求**。
- 授权与留痕：**强项**（分级分类、脱敏、审计、流转控制）。
- 商业：安全预算，项目制。

**与我们的关系**：**最值得借鉴、也最容易结盟的一类**。他们缺"业务判断的可执行表达"；我们缺"合规话语与审计导出"。我们的"用途白名单 / 金额上限 / 不得转售 / 拒绝留痕 / 分级披露"正好是他们的语言。

### 第 4 类：企业智能体平台型

代表：**滴普科技 DeepWorks**、**零数科技**等；以及 WorkBuddy 这类通用助手的"专家 / 技能 / 连接器"体系。参见 [滴普科技 DeepWorks](https://www.ncsti.gov.cn/kjdt/scyq/zgckxc/zgcdt/202607/t20260723_251800.html)、[零数科技专访](http://www.cb.com.cn/index/show/jr/cv/cv135271032343)。

- 谁写规则：**提示词与工作流**（人设 + 方法论 + 工具链）。
- 权威来源：**模型 + 平台**；平台通常自带免责声明。
- 授权与留痕：会话记录 + 工具调用日志。
- 商业：席位 + 积分 + 企业版。

**与我们的关系**：**最直接的对照**。他们卖"AI 像一个专家"，我们卖"专家的方法被调用并可追责"。前者规模化，后者进合规与责任敏感场景。

## 四、我们的位置（一张图记住）

```
              数据规模 / 建模复杂度  →
   低 ────────────────────────────────────────────── 高
   │  通用水印：企业智能体平台（提示词型）
   │      · 快、便宜、通用
   │      · 权威来自模型 ✗
   │
   │        ★ 我们：方法可执行 + 授权 + 留痕 + 分级披露
   │           · 权威来自具名专家 / 团队 ✓
   │           · 结论确定性、可溯源 ✓
   │           · 私有优先、方法不外泄 ✓
   │
   │  企业本体 / 决策 OS（重实施，大单）
   │  语义层 / 图谱（数据团队主导）
   ↓
   治理与追责强度
```
**一句话定位**：我们不是"更大的知识库"，我们是**"决策服务的治理层"**——把专家方法变成可授权、可计费、可审计的对外服务。

## 五、升级必须补的清单（按优先级）

1. **组织与多租户**：企业 / 部门 / 岗位 / 外部合作方四层主体；主体与外部身份源对接（SSO / AD）。
2. **授权升级**：RBAC → ABAC；组织审批流；授权变更留痕；离职 / 转岗自动回收。
3. **方法治理**：方法（切片）的版本、评审、生效 / 失效、变更影响面（改了会影响哪些在跑的调用）。
4. **审计与合规**：审计导出（CSV / SIEM）、留存期限策略、数据分级分类对齐、等保与信创适配。
5. **集成**：ERP / OA / CRM / 数据仓库 / 工单 / 文档库的连接器；不再只是本机 MCP。
6. **部署与运维**：私有化安装包、升级回滚、监控告警、备份恢复、SLA。
7. **商业闭环**：订阅 + 席位 + 按次计费；对公结算 / 发票；用量报表（谁用了哪个方法、花了多少）。
8. **易用性**（我们最大短板）：模板化创建、边界引导、一键实例化、示例库；把"配边界 / 批准程序"变成引导步骤。

**顺手要修的已知缺陷**：重建切片会丢边界配置；保存空值会把用途 / 上限 / 有效期写空；目录里判定条目缺 `slice_id`；引擎校验不检查"选项字段被当数字比较"。

## 六、落地路径（建议）

1. **单点试点**（1 个部门、1 类判断）：法务的合同风险判断 / 风控的尽调结论 / 保险的规则化核保。**只做一条切片，做到可署名、可留痕、可复核。**
2. **部门内推广**：把方法模板化、把边界与审批流程固化；接上企业的身份源与一个业务系统。
3. **对外服务**：把切片作为"对外可调用服务"提供给合作方（律所→客户、评估机构→委托方、保险公司→代理渠道），此时按次计费与分级披露才真正产生价值。

## 七、风险与反面意见

- **"企业为什么不直接用通用助手 + 提示词？"** 因为责任敏感场景要的是**可签名、可复核、可审计**；提示词给不了。但**如果我们的易用性上不去，客户会先选便宜的通用助手**——这是最现实的风险。
- **"企业为什么要买一个"新"平台？"** 所以不要以"平台"姿态入场，以**"合规与审计的补丁"**入场，挂在他们已有的数据底座上。
- **"私有化部署成本高"**：先用单机 / 单部门试点证明价值，再谈企业级。
- **标准未定**：应用侧协议（如 SAEP 一类）仍在公示期；我们只做**个人 / 企业侧的轮廓**，不另造传输层。
