# 专业技能场景 · 起草与核对界面重设计（待确认）

> 状态：**设计稿，尚未写代码**。确认后按此实现。
> 目标：① 一眼找到"在哪起草框架" ② 提供三种输入方式，各管一类人 ③ 核对与微调集中在一处。

---

## 一、现状与问题（先把账说清）

**现状**
- 起草入口有两个：**方式一 让模型起草**、**方式二 一行一条自己写**，并排放在「第二步」。
- 「一行一条」实际有 **8 个框**：需要调用方提交的信息 / 判断的基准线 / 我观察什么 / 几个观察点一起出现时 /
  例外情况 / 哪个更重要 / 我的依据 / 打分线。
- 「对外调用与交付」这一组里的三项 —— **对外调用的边界 / 对外交付时附上的说明 / 计费** ——
  **只能在上面的表格面板里改，一行一条里没有它们**。

**问题**
1. **找不到起草的地方**：入口混在页面中部，和切片列表、第三步挤在一起，没有"我现在要起草"的明确落点。
2. **缺少"一次贴完"的方式**：习惯先在手边（Word、笔记）把内容写好的人，只能一行一行往 8 个框里搬。
3. **一行一条不完整**：对外那三项缺席，而它们恰恰是**要给调用方看的**，最该一次写清。
4. 三种方式之间**没有关系说明**：用户不知道自己适合哪种、也不知道可以混用。

## 二、目标结构（三步不变，第二步重构）

```
场景切片 → 专业
  第一步 · 选场景与我的切片            （不动）
  第二步 · 起草框架：三种方式，任选其一或混用   ← 本次重做
  第三步 · 核对与微调                  （不动：已按受众分两组、带目录、带条数）
```

**找到起草处（问题 1 的解法）**
- 「第二步」顶部固定一行说明 + 三张**方式卡片**（等宽、可点选、选中高亮）：
  ```
  ┌─ 方式一 · 让模型起草 ────────┐ ┌─ 方式二 · 一次性写入 ────────┐ ┌─ 方式三 · 逐行输入 ────────┐
  │ 我说一段话，它出草稿          │ │ 我在别处写好，整篇贴进来      │ │ 我对着 11 个框，一条一条填   │
  │ 适合：还没想清楚结构          │ │ 适合：已经在纸上写好          │ │ 适合：喜欢边想边写、逐条推敲 │
  └─────────────────────────────┘ └─────────────────────────────┘ └─────────────────────────────┘
  ```
- 点哪张卡，就展开哪种输入界面；**同一时刻只展开一个**（其余收起为卡片），页面不再同时堆三套界面。
- 卡片下方一句：**"三种方式改的是同一份框架，随时可以切换，先写的不会丢。"**
- 选中的方式**记住**（本次会话内），刷新后仍有默认值：**方式一**（首次使用最省力）。

## 三、方式一 · 让模型起草（保持，微调）

- 现状保留：一段自然语言 → 生成草稿 → 进第三步核对。
- 微调：
  - 输入框上方写清"**写四件事**"：我看哪几件事 / 什么算异常 / 几件事同时出现时怎么变 / 什么情况例外。
  - 生成后**自动跳到第三步**，并在第三步顶部给一条提示："**草稿已生成，请逐项核对**"。

---

## 四、方式二 · 一次性写入（新增，带样例）

**做什么**：一个大文本框，把**整篇**粘进去，一次提交，一次性生成整份框架。

**怎么写**：沿用"一行一条"的语法，用**小节标题**分段（标题独占一行，用【】括起来）：

```
【判断的基准线】
基准 1.3
监管环境=收紧 → -0.10

【我观察什么】
团队流失高 = 核心团队流失风险 等于 高

【几个观察点一起出现时】
团队流失高 且 现金流危机 → 估值偏高（高）

【例外情况】
技术已专利化 且 技术壁垒极高 → 团队流失权重 ×0.5

【哪个更重要】
现金流危机 > 团队流失高

【我的依据】
反垄断法第二十六条 → 团队流失高 且 现金流危机

【打分线（分数怎么变成结论）】
打分 0.5 以上 → 估值偏高（高）
其余 → 估值中性（中）

【对外调用的边界】            ← 新增
金额上限 1000000
允许用途 估值、尽调
不得转售

【对外交付时附上的说明】       ← 新增
强在哪：普通判断只看一个指标，本判断还看行业与周期
资历：执业 15 年
档位：audit
有效期：30 天

【需要调用方提交的信息】        ← 属于对外（放在这一组最前面）
市盈率 ｜ 数字
现金流状况 ｜ 选项 ｜ 健康、紧张、危机

【对外调用的边界】            ← 新增
金额上限 1000000
允许用途 估值、尽调
不得转售

【对外交付时附上的说明】       ← 新增
强在哪：普通判断只看一个指标，本判断还看行业与周期
资历：执业 15 年
档位：audit
有效期：30 天

【计费（演示）】              ← 新增
每次 （留空表示不计费）
```

**界面元素**
1. 大文本框（等宽字体，高约 20 行）。
2. 三个按钮：**[填入样例]**（把上面整篇填进去，供改写）· **[提交解析]** · **[清空]**。
3. 样例说明一句："样例里的数字与名字都是**占位**，请全部换成你自己的；**计费留空即不计费**。"
4. 解析结果区：按小节列出 **已导入 N 条 / 第 M 行有问题（原样 + 原因）**；
   有问题的小节**不覆盖**已核对好的内容（避免写错一处毁掉全篇）。
5. 解析成功后提示："已导入，去**第三步**核对"。

**为什么这样设计**
- 满足"在别处写好、一次贴进来"的习惯，又**不引入第二套语法**（与方式三同一语法）。
- **小节标题**是唯一新增的语法，它让"哪一行属于哪一节"不再靠框的位置。

## 五、方式三 · 逐行输入（8 个框 → 11 个框）

把方式二的**同一语法**拆成 11 个小框，每框一节，框内一行一条。
框序与分组一致：**1–7 我的判断模型**，**8–11 对外调用与交付**（其中 8 是「需要调用方提交的信息」，9/10/11 是本次新增）：

| 序 | 框名 | 写什么 | 例子（占位） |
|---|---|---|---|
| 1 | 判断的基准线 | 基准值 / 条件 → 调整量 | `基准 1.3` |
| 2 | 我观察什么 | 信号 = 字段 比较 值 | `团队流失高 = 核心团队流失风险 等于 高` |
| 3 | 几个观察点一起出现时 | 信号 且 信号 → 结论（严重度）| `甲 且 乙 → 估值偏高（高）` |
| 4 | 例外情况 | 条件 → 改写方式 | `甲 且 乙 → 团队流失权重 ×0.5` |
| 5 | 哪个更重要 | 更重要的 > 次重要的 | `现金流危机 > 团队流失高` |
| 6 | 我的依据 | 依据名 → 适用信号 | `反垄断法第二十六条 → 团队流失高` |
| 7 | 打分线 | 打分 X 以上/以下/其余 → 结论 | `打分 0.5 以上 → 估值偏高（高）` |
| 8 | 需要调用方提交的信息（对外组第 1 个）| 名称 ｜ 类型 ｜ 选项 | `市盈率 ｜ 数字` |
| **9** | **对外调用的边界**（新增）| 金额上限 / 允许用途 / 不得转售 | `金额上限 1000000` |
| **10** | **对外交付时附上的说明**（新增）| 强在哪 / 资历 / 档位 / 有效期 | `有效期：30 天` |
| **11** | **计费（演示）**（新增）| 每次 <价格> <币种> | `每次 （留空＝不计费）` |

**排版改进**
- 11 个框**按受众分两组**，与第三步一致：
  **我的判断模型**（7 个：判断的基准线 · 我观察什么 · 几个观察点一起出现时 · 例外情况 · 哪个更重要 · 我的依据 · 打分线）
  ／**对外调用与交付（写给调用方）**（4 个：需要调用方提交的信息 · 对外调用的边界 · 对外交付时附上的说明 · 计费），组标题带一句说明。
- 每组可**整组折叠**（默认展开"我的判断模型"、收起"对外"），避免一次看到 11 个框。

## 六、三种方式的关系（必须讲清楚）

```
方式一  自然语言 → 草稿      ┐
方式二  整篇文本 → 框架      ├─→ 同一份框架 → 第三步核对与微调
方式三  分框文本 → 框架      ┘
```
- **可以混用**：先让模型出草稿，再切到方式三逐条改；或方式二贴一半，剩下的用方式三补。
- **不覆盖已核对内容**：若某个小节解析失败，只报错，不动该小节。
- 切方式时给一次提示："切过去不会丢内容；只有按下提交时才会写入。"
