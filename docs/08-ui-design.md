# 界面设计：从"场景工具"到"个人本体"（v0.1 草案）

> 依据 `docs/07-circles-and-profile-items-design.md` 的模型设计。
> 只画结构与交互，不写代码；沿用现有视觉语言（浅底、卡片、8px 圆角、14/17px 字号），不新造一套设计系统。

## 一、信息架构：两层分组，11 个入口

现在的侧栏是"场景工具"的排法（场景切片、场景实例、场景预演、交付、记录…），人是主角之后，需要重排。

```
我的世界
  · 总览        一眼看到：最近谁用过我的什么、哪些事到期、哪些关系变冷
  · 我          身份 / 身体 / 资质 / 紧急联系人      ← 资料项（profile-items）
  · 圈          家人 / 朋友 / 工作 / 客户 / 同学 / 服务 / 组织   ← 圈与成员
  · 事          日程 / 约定 / 承诺 / 合同 / 保修
  · 地          常住地 / 常用地址 / 行程
  · 财          账户 / 资产 / 保险 / 订阅 + 流水
  · 识          笔记 / 作品 / 照片 / 证据 / 知识卡

规则与能力
  · 界          授权规则 / 每次预填 / 红线 / 偏好 / 禁区
  · 器          设备 / 智能体 / 服务账号 / MCP 接入
  · 用          场景切片 / 场景预演 / 对外交付与反馈
  · 记录        判定记录 / 交付记录 / 资料使用记录
```

### 旧菜单如何搬家（避免用户迷路）

| 现在的菜单 | 新位置 |
|---|---|
| 主体 | 并入「圈」的成员与「器」的智能体（主体仍存在，但不再单独当一级） |
| 个人资料 | 并入「我」（资料项） |
| 场景切片 / 场景实例 / 场景预演 | 移到「用」 |
| 对外交付与反馈 | 移到「用」下的标签页 |
| 判定记录 | 移到「记录」 |
| 智能体授权 / 智能体接入 / 服务监控 | 移到「器」 |
| 模型服务 / 显示与语言 | 保留在「器 → 设置」 |
| 账号与安全 | 保留在右上角头像菜单（不再占一级） |

## 二、全局交互原则（三条，贯穿所有页面）

1. **敏感先掩码**：所有资料项、流水金额、联系方式默认掩码；点「查看」需二次确认，并写一条记录。
2. **每次动作留痕**：授权、查看、导出、修改，全部留一条；页面上有入口可查（"谁看过"）。
3. **拒绝要能解释**：任何"不能"的提示，必须说清是哪条规则、哪一圈、哪个字段。

```
│ ┌────────────────────────────────────────────────────────┐ │

│ │ 默认：可看我的行程空闲，不给具体内容                     │ │
│ │                                    [ 管理 ] [ 授权 ]    │ │
│ └────────────────────────────────────────────────────────┘ │
│ ┌────────────────────────────────────────────────────────┐ │
│ │ 工作          工作 · 12 人 · 最近互动 昨天    [敏感]     │ │

```

要点：卡片只放"决策所需"的五行字；敏感级用一枚小标签；主操作固定在最右。

## 四、圈：列表与详情

### 列表
同上。排序支持"最近互动 / 人数 / 敏感级"。

### 详情（`圈 / 工作`）

```
┌────────────────────────────────────────────────────────────┐
│ ← 圈                                                        │
│ 工作   工作圈 · 12 人 · [敏感]                  [ 编辑 ]    │
│ 我在这一圈的身份：下属                                       │
├────────────────────────────────────────────────────────────┤
│ [ 成员 12 ] [ 圈级授权 3 ] [ 变更记录 ]                       │
├────────────────────────────────────────────────────────────┤
│ 成员                                              [ + 添加 ] │
│ ┌──────────┬────────┬────────┬──────────┬───────────────┐  │
│ │ 张三      │ 同事    │ 亲近    │ 昨天      │ [移出][查看] │  │
│ │ 李四      │ 客户    │ 一般    │ 3 个月前  │ [移出][查看] │  │
│ └──────────┴────────┴────────┴──────────┴───────────────┘  │
│ ⚠ 移出会立即影响 2 条授权（今天起不再生效），会写入变更记录   │
├────────────────────────────────────────────────────────────┤
│ 圈级授权                                                    │
│  · 可看：我的行程空闲时间（不含具体内容）  [ 生效 ]          │
│  · 可看：我的资质与公开身份                [ 生效 ]          │
│  · 不可看：联系方式、证件、健康            [ 拦截 ]          │
└────────────────────────────────────────────────────────────┘
```

要点：
- **成员行只显示"关系"，不显示对方资料**（备注另有一处只读展示，且标红"仅本机可见"）。
- 移出成员必须给"影响面"，并写变更记录——这是最容易出事的地方。
- 圈级授权与"场景授权"分开显示，避免混为一谈。

## 五、我：资料项（profile-items）

```
┌────────────────────────────────────────────────────────────┐
│ 我                                     [ + 添加资料项 ]     │
│ 身份、身体、资质、紧急联系人。默认掩码，查看要确认。         │
├────────────────────────────────────────────────────────────┤
│ 身份                                                        │
│  姓名        张三                          [critical] [查看]│
│  身份证号    33**************34  已验证     [critical] [查看]│
│  手机号      13*******00          已验证     [sensitive][查看]│
│ 身体                                                        │
│  过敏        青霉素                       [critical] [查看]│
│  血型        A 型                          [normal]  [查看]│
│ 资质                                                        │
│  律师执业证  沪 2019 ****                  [sensitive][查看]│
│ 紧急联系人  王五 · 138****8888              [critical][查看]│
├────────────────────────────────────────────────────────────┤
│ 点「查看」→ 弹出：确认查看明文？本次查看会写入记录。 [取消][确认]│
└────────────────────────────────────────────────────────────┘
```

要点：
- 按 `kind` 自动分组（身份/身体/资质/紧急），不再让用户自己分类。
- 每行右侧永远有「查看」与「被谁用过」两个入口（后者可省，放入详情）。
- 证件类默认 `critical`，红色小标签，视觉上和其他项区分开。

## 六、财：资产与流水

### 资产
```
财
[ 账户 3 ] [ 资产 2 ] [ 保险 1 ] [ 订阅 4 ]
  工资卡    **** 1234   招商银行   [restricted]  [编辑]
  车险      2027-03-01 到期            [到期提醒: 开]
```

### 流水（独立标签页，默认收起）

```
[ 流水 ]   2026 年 10 月 · 共 128 笔 · 支出 6,420
┌────────┬──────────────┬────────┬────────┐
│ 10-20  │ 某商户        │ -38.5  │ 餐饮   │
│ 10-19  │ 某超市        │ -210.0 │ 日用   │
└────────┴──────────────┴────────┴────────┘
⚠ 流水属于最敏感的数据：默认不参与任何对外授权，不进智能体可读范围。
```

要点：
- 流水默认**折叠**，需要主动点开（避免随手被看到）。
- 明确写出"不参与对外授权"，让用户放心。
- 金额默认显示，不做掩码（否则没法对账）——但页面顶部标注敏感。

## 七、界：授权与边界（现有能力的新家）

```
界
[ 授权规则 ] [ 每次预填 ] [ 红线 ] [ 偏好与禁区 ]

授权规则
  · 给「工作圈」看我的行程空闲      [生效]  影响 12 人   [暂停]
  · 给「家人」看我的健康记录        [生效]  影响 6 人    [暂停]
  · 给某酒店：姓名+证件号 · 10 分钟  [一次性] 已过期
  · 给某航司：姓名+证件号           [被拒绝] 原因：不在允许用途内
```

要点：
- 新增"授权对象"选择器：**个体 / 圈 / 一次性**三选一（对应 `grantee_kind`）。
- 生效中的规则必须显示"影响多少人"。
- 被拒绝的记录要能点开看原因——这是这套产品最值钱的部分。

## 八、器：设备与智能体

```
器
[ 设备 4 ] [ 智能体 2 ] [ 服务账号 3 ]

智能体
┌────────────────────────┬──────────┬────────┬────────────┐
│ WorkBuddy（本机 MCP）    │ 已批准    │ 昨天    │ [吊销][看范围]│
│ 某笔记助手               │ 待批准    │ —       │ [批准][拒绝] │
└────────────────────────┴──────────┴────────┴────────────┘
```

要点：智能体清单从明文 json 迁进本体后，这个页面才有意义；"看范围"要能列出具体能读哪些集合。

## 九、移动端（手机是第一现场）

```
┌─────────────────────────────┐
│ 圈                      +   │  ← 标题栏 + 主操作
│ 一圈人、一个默认边界         │
│ ┌─────────────────────────┐ │
│ │ 家人   6 人 · 3 天前     │ │  ← 卡片高度 ≥ 72px，点整卡进详情
│ │ 可看行程空闲              │ │
│ └─────────────────────────┘ │
│                             │
├─────────────────────────────┤
│ 总览   我   圈   界   更多    │  ← 底部 5 个 tab
└─────────────────────────────┘
```

要点：
- 底部 5 个 tab 只放高频（总览/我/圈/界/更多），其余收进「更多」。
- 详情页全屏，主操作放底部浮动按钮（拇指可达）。
- 表格在手机上改为"两行卡片"：第一行名称+标签，第二行摘要+操作。

## 十、空状态、加载与错误

| 场景 | 文案与动作 |
|---|---|
| 圈为空 | 「还没有圈。先建一个"家人"，或从通讯录导入。」+ 两个按钮 |
| 资料项为空 | 「先加一项：姓名、身份证号，或过敏信息。」+ 添加 |
| 流水为空 | 「还没有流水。可以从银行导出的对账单导入。」 |
| 加载中 | 骨架屏（卡片轮廓），不转圈 |
| 写入被拒 | 「数据校验未通过：<具体属性与原因>」（现有 api() 已能解析 SHACL 报告） |
| 权限不足 | 「这条规则被"工作圈"的边界拦住了：不得读取联系方式。」+ 查看规则 |

## 十一、分三期实现（建议）

```
第一期（能看、能管，不做智能联动）
  总览改版 · 我（资料项）· 圈（列表+详情+成员）· 界（授权对象可选圈）· 器（智能体清单）

第二期（能提醒）
  事（约定/到期）· 财（资产+流水）· 观里的"该续保了""三个月没联系"提示

第三期（能联动）
  识（笔记/照片）· 地（行程）· 圈与场景预演联动（按圈自动选预填项）
```

## 十二、已定事项（2026-10 拍板）

| # | 问题 | 决定 |
|---|---|---|
| 1 | 11 个入口是否太多 | **不多**，保留 11 个（两层分组） |
| 2 | 主体不再单独当一级菜单 | **可以**，主体并入「圈」的成员与「器」的智能体 |
| 3 | 流水页是否要每次输口令片段 | **不要**；已整体加密，流水页默认折叠即可 |
| 4 | 手机端是否第一期就做 | **后面考虑**，第一期只做桌面端 |

## 十三、第一期施工顺序（据此开工）

1. 导航骨架：两层分组 + 11 个入口（新入口先给占位页，不做假数据）
2. 「我」：由现有「个人资料」改名并扩为资料项分组
3. 「圈」：列表 + 详情 + 成员（依赖 07 文档的 circles / circle-members 建模）
4. 「界」：授权对象改为可选中个体 / 圈 / 一次性
5. 「器」：智能体清单从明文 json 收编进本体后，接入此页
